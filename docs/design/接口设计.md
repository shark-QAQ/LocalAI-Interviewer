基于上一轮的系统设计，我将接口设计细化为 **RESTful + SSE（Server-Sent Events）** 混合风格。所有接口遵循 **无状态令牌（本地环境建议直接使用 Session ID）** 鉴权，返回格式统一。

以下是 **API 接口详细设计文档（OpenAPI 3.0 风格）**，包含请求/响应示例及核心 `SSE` 流式协议。

---

## 1. 通用规范

| 规范项           | 说明                                                         |
| :--------------- | :----------------------------------------------------------- |
| **Base URL**     | `http://localhost:8000/api/v1`                               |
| **Content-Type** | `application/json` (普通接口) / `text/event-stream` (SSE 接口) |
| **字符编码**     | UTF-8                                                        |
| **错误统一格式** | `{"code": "ERROR_CODE", "message": "描述", "timestamp": 1234567890}` |
| **SSE 事件类型** | `question` (提问), `evaluation` (上轮打分), `thinking` (模型思考中), `done` (结束) |

---

## 2. 模块一：项目管理 & 知识库索引（Indexing）

### 2.1 初始化/更新项目代码索引
将本地代码路径录入系统，触发全量/增量向量化。

- **Endpoint**：`POST /projects/init`
- **Request**：
```json
{
  "project_name": "my-payment-system",  // 自定义别名，必填
  "code_path": "/Users/xxx/workspace/payment-core", // 绝对路径，必填
  "force_rebuild": false // true则删除旧库重建，false则增量更新
}
```
- **Response (200 OK)**：
```json
{
  "project_id": "proj_abc123",
  "status": "indexing", // 或 "completed" 若代码量小
  "total_chunks": 0,    // 索引完成后可通过 GET 查询
  "estimated_time": 30  // 预计耗时（秒）
}
```
- **异步查询进度**：`GET /projects/{project_id}/status`
```json
{
  "project_id": "proj_abc123",
  "index_status": "processing", // idle | processing | completed | failed
  "chunk_count": 1520,
  "last_indexed_at": "2026-09-02T10:00:00Z"
}
```

## 3. 模块二：简历管理（Resume）

### 3.1 上传并解析简历
- **Endpoint**：`POST /resumes/upload`
- **Content-Type**：`multipart/form-data`
- **Form-Data**：
  - `file`: PDF 或 DOCX 文件（限制 < 10MB）
  - `candidate_name`: (可选) 若未填从文件元数据读取
- **Response (200 OK)**：
```json
{
  "resume_id": "res_xyz789",
  "parsed_data": {
    "name": "张三",
    "email": "zhangsan@example.com",
    "years_of_experience": 5,
    "skills": ["Java", "Spring Boot", "Redis", "Kafka", "Docker", "MySQL"],
    "projects": [
      {
        "name": "高并发秒杀系统",
        "description": "基于Redis+MQ实现...",
        "tech_stack": ["Spring Boot", "Redis", "RocketMQ"]
      }
    ],
    "education": { "degree": "硕士", "major": "计算机科学" }
  }
}
```

### 3.2 获取/修改解析结果（人工修正）
- **Endpoint**：`GET /resumes/{resume_id}` 
- **Endpoint**：`PUT /resumes/{resume_id}` (支持人工修正技能清单，防止 OCR 错漏)

## 4. 模块三：面试会话管理（Session）

### 4.1 开启面试
- **Endpoint**：`POST /interviews/sessions`
- **Request**：
```json
{
  "resume_id": "res_xyz789",
  "project_id": "proj_abc123",
  "target_position": "Java高级开发工程师", // 可选，影响问题难度
  "max_rounds": 8,       // 默认 8 轮
  "difficulty": "mid"    // junior | mid | senior，默认根据年限自动推断
}
```
- **Response (201 Created)**：
```json
{
  "session_id": "sess_666",
  "status": "waiting_for_question", // 等待出第一题
  "initial_question": null          // 稍后通过 SSE 获取第一题（或等待前端调用下一题）
}
```
> **设计决策**：不在此处直接返回第一题，遵循“一问一答”的严格时序，方便前端统一处理流式渲染。

## 5. 模块四：核心面试流（SSE 实时交互）⭐

这是最关键的接口。前端携带用户回答（或空参数获取首题）请求此接口，**服务端以 SSE 流式返回 AI 的实时思考与提问**。

- **Endpoint**：`POST /interviews/sessions/{session_id}/interact`
- **Request Body**：
```json
{
  "user_answer": "我认为分布式锁可以用 Redisson 实现，加锁时设置过期时间防止死锁..." 
  // 若为 null 或空字符串，表示“请出第一题”
}
```
- **Response Headers**：
```
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive
```
- **SSE 事件流序列（按时间顺序）**：

| 事件类型 (event) | 数据字段 (data) 示例                                         | 前端行为                           |
| :--------------- | :----------------------------------------------------------- | :--------------------------------- |
| `thinking`       | `{"message": "正在分析你的简历和代码库..."}`                 | 显示 Loading 动态文案              |
| `intro_eval`     | `{"score": 7.0, "comment": "介绍了项目背景，可再点明与你应聘岗位的关联", "dimensions": {"clarity":7, "substance":8, "fit":6}}` | 候选人对开场白的**自我介绍**后，弹出独立“自我介绍点评”小窗（表达/内容/匹配维度，非代码技术评分）；不计入最终报告与技能覆盖 |
| `evaluation`     | `{"round": 1, "score": 7.5, "comment": "回答要点正确，但遗漏了续期机制", "dimensions": {"depth":8, "logic":7, "integrity":7}}` | 弹出一轮技术问答后的评分小窗（软性展示）  |
| `question`       | `{"round": 2, "content": "我看到你们项目里用Redisson实现了锁，如果Redis主节点宕机，从节点还未同步锁数据，此时新的请求来了会发生什么？你如何优化？", "tags": ["Redis", "分布式一致性"]}` | **渲染新题目**（内容已由后端裁剪为纯问题文本），并让用户输入框可用 |
| `done`           | `{"final": true, "reason": "已达到最大轮次"}`                | 关闭 SSE 连接，自动跳转报告页      |

**⭐ 核心设计细节**：
- 每次请求只能推进一轮。前端发送 `user_answer`，后端返回 **1 条点评（自我介绍为 `intro_eval`，技术问答为 `evaluation`）+ 1 条 `question`**（或 `done`）。
- 自我介绍发生在技术题之前，不携带“深度/逻辑/完整”代码评分，避免无参照对象时产生胡言乱语式打分。
- **上下文保持**：后端自动缓存历史对话（最近 3 轮完整问答 + 所有摘要），无需前端维护。
- **断线重连**：若网络中断，前端可重新调用此接口并携带 `user_answer=null`，后端会基于 `session_id` 恢复并返回当前待回答的题目（幂等性设计）。

## 6. 模块五：八股文生成（Cram）

### 6.1 生成八股文备考文档
- **Endpoint**：`POST /cram/generate`
- **Request**：
```json
{
  "project_id": "proj_abc123",
  "resume_id": "res_xyz789", // 可选，若不传则只基于代码库生成通用八股
  "focus_areas": ["JVM调优", "分布式事务", "缓存设计"], // 可选，空则自动抽取高频技能
  "format": "markdown" // 或 "json"
}
```
- **Response (200 OK)**：
```json
{
  "task_id": "cram_task_001",
  "status": "generating",
  "estimated_seconds": 45
}
```
- **异步获取结果**：`GET /cram/tasks/{task_id}` (轮询)
```json
{
  "task_id": "cram_task_001",
  "status": "completed",
  "content": "# 八股文：支付系统高频考点\n\n## 1. 分布式事务\n**Q**: 你们的支付系统如何保证数据最终一致性？\n**A**: 基于RocketMQ事务消息...\n\n## 2. JVM 内存模型\n...",
  "word_count": 3500
}
```

## 8. 错误码清单（业务级）

| Code                   | HTTP Status | 含义                                     |
| :--------------------- | :---------- | :--------------------------------------- |
| `PROJECT_NOT_FOUND`    | 404         | 项目 ID 不存在                           |
| `RESUME_PARSE_FAILED`  | 400         | PDF 解析失败（加密或图片型 PDF）         |
| `SESSION_EXPIRED`      | 410         | 面试会话超时（默认 2 小时无操作）        |
| `INDEXING_IN_PROGRESS` | 409         | 当前项目正在建索引，无法启动面试         |
| `LLM_TIMEOUT`          | 504         | Ollama 推理超时（> 60s）                 |
| `RAG_EMPTY`            | 404         | 代码库未检出任何有效代码块，无法生成问题 |

## 9. 接口调用时序串联（前端典型流程）

1. `POST /projects/init` (建库，轮询 `/status` 直到完成)
2. `POST /resumes/upload` (拿简历 ID)
3. `POST /interviews/sessions` (拿 session_id)
4. 开启 EventSource 或 循环 `fetch`:
   - `POST /sessions/{id}/interact` (body: `{"user_answer": null}`) → 收到 `question` 事件，展示第一题。
   - 用户输入答案后，再次 `POST .../interact` (body: `{"user_answer": "..."}`) → 收到 `evaluation` (上一轮评分) + `question` (下一题)。
   - 重复直到收到 `done`。
5. `GET /interviews/sessions/{id}/report` (看结果)
6. (可选) `POST /cram/generate` + 轮询 `GET /cram/tasks/{id}` 拿八股文。

## 10. 注意事项（防坑指南）

- **Ollama 并发限制**：Qwen 和 BGE-M3 不能同时跑高频推理。后端需设计**请求队列**（使用 `asyncio.Queue`），对 `/interact` 接口做全局互斥锁，防止显存溢出。
- **SSE 超时设置**：Nginx 或 Uvicorn 需配置 `timeout=600`，因为生成深度问题可能耗时 10~20 秒。
- **简历隐私**：所有 PDF 解析文本仅在内存中处理，**不落地存储**，只存 `parsed_data` 的 JSON 到 SQLite（可加密字段）。
