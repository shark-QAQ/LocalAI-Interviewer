基于前两轮的系统与接口设计，我将数据库设计分为 **关系型元数据库（SQLite/PostgreSQL）** 和 **向量特征库（ChromaDB）** 两部分。这套设计充分考虑了**本地化轻量部署**（SQLite）与**生产级扩展性**（PostgreSQL）的兼容，并针对 **BGE-M3 的 1024 维向量**做了索引优化。

## 2. 关系型数据库详细设计（DDL）

**推荐使用 SQLite（文件数据库）**，零配置且支持 JSON1 扩展。若代码库超 10 万 Chunks，可平滑迁移至 PostgreSQL。

### 2.1 项目表 (`projects`)
存储被索引的代码仓库元信息。

```sql
CREATE TABLE projects (
    id              TEXT PRIMARY KEY DEFAULT (lower(hex(randomblob(4))) || '-' || ...), -- 简写，可用 UUID
    name            TEXT NOT NULL,                -- 项目别名
    repo_path       TEXT NOT NULL UNIQUE,         -- 本地绝对路径，唯一约束防止重复
    language        TEXT,                         -- 自动检测主语言 (Java/Python/Go)
    last_indexed_at DATETIME,                     -- 最后一次索引完成时间
    chunk_count     INTEGER DEFAULT 0,            -- 向量库中的文档块数量
    index_status    TEXT DEFAULT 'idle' CHECK(index_status IN ('idle','processing','completed','failed')),
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_projects_status ON projects(index_status);
CREATE INDEX idx_projects_path ON projects(repo_path);
```

### 2.2 简历表 (`resumes`)
存储解析后的候选人信息，**`skills` 和 `parsed_data` 使用 JSON 字段**，便于灵活扩展而不改表结构。

```sql
CREATE TABLE resumes (
    id              TEXT PRIMARY KEY DEFAULT (uuid_generate_v4()), -- SQLite无原生UUID，可用应用层生成
    candidate_name  TEXT NOT NULL,
    email           TEXT,
    raw_text_hash   TEXT UNIQUE,                  -- 用于去重，避免重复上传相同简历
    parsed_data     TEXT NOT NULL,                -- JSON: 包含项目经历、教育背景等完整信息
    skills          TEXT NOT NULL,                -- JSON数组: ["Java","Redis","Docker"]
    years_exp       REAL,                         -- 浮点数，如 5.5 年
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 虚拟列 + 索引（SQLite 3.37+ 支持，便于快速检索技能）
CREATE INDEX idx_resumes_skills ON resumes(skills); 
-- 若使用 PostgreSQL，可用 GIN 索引: CREATE INDEX idx_resumes_skills ON resumes USING GIN (skills);
```

### 2.3 面试会话表 (`interview_sessions`)
管理每次面试的全生命周期。

```sql
CREATE TABLE interview_sessions (
    id              TEXT PRIMARY KEY,
    resume_id       TEXT NOT NULL REFERENCES resumes(id) ON DELETE CASCADE,
    project_id      TEXT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
    target_position TEXT,                         -- 目标岗位
    difficulty      TEXT DEFAULT 'mid' CHECK(difficulty IN ('junior','mid','senior')),
    max_rounds      INTEGER DEFAULT 8,
    current_round   INTEGER DEFAULT 0,            -- 已完成的轮数
    status          TEXT DEFAULT 'init' CHECK(status IN ('init','questioning','evaluating','terminated','reported')),
    context_summary TEXT,                         -- 对话摘要（滑动窗口压缩后的文本）
    started_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    ended_at        DATETIME,
    expired_at      DATETIME                      -- 2小时无操作自动过期
);

CREATE INDEX idx_sessions_resume ON interview_sessions(resume_id);
CREATE INDEX idx_sessions_project ON interview_sessions(project_id);
CREATE INDEX idx_sessions_status ON interview_sessions(status);
```

### 2.4 消息明细表 (`messages`)
记录每一轮的问答与 AI 评价，**`score_json`** 存储维度和分项得分。

```sql
CREATE TABLE messages (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id      TEXT NOT NULL REFERENCES interview_sessions(id) ON DELETE CASCADE,
    round_num       INTEGER NOT NULL,              -- 第几轮
    role            TEXT NOT NULL CHECK(role IN ('user', 'assistant', 'system_eval')),
    content         TEXT NOT NULL,                 -- 完整对话内容
    tokens_used     INTEGER,                       -- 该消息消耗的 Token 数（统计用）
    score_json      TEXT,                          -- JSON: {"depth": 7.5, "logic": 8.0, "integrity": 6.5, "avg": 7.3}
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_messages_session ON messages(session_id);
CREATE INDEX idx_messages_round ON messages(session_id, round_num);
```

### 2.5 代码谱系图 (`function_graph`) —— 可选但强烈推荐
通过 AST 解析提取的函数调用关系，用于 **“连环追问”**（例如：问完 A 函数实现，马上追问其调用的 B 函数细节）。

```sql
CREATE TABLE function_graph (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    project_id      TEXT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
    caller_func     TEXT NOT NULL,                 -- 调用者函数名（含类路径）
    callee_func     TEXT NOT NULL,                 -- 被调用者函数名
    file_path       TEXT NOT NULL,                 -- 所在文件
    call_line       INTEGER,                       -- 调用所在行号
    call_count      INTEGER DEFAULT 1,             -- 调用频次（静态分析）
    UNIQUE(project_id, caller_func, callee_func, file_path)
);

CREATE INDEX idx_graph_caller ON function_graph(project_id, caller_func);
CREATE INDEX idx_graph_callee ON function_graph(project_id, callee_func);
```

### 2.6 八股文生成任务表 (`cram_tasks`)
用于异步生成大篇幅八股文，避免阻塞主线程。

```sql
CREATE TABLE cram_tasks (
    id              TEXT PRIMARY KEY,
    project_id      TEXT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
    resume_id       TEXT REFERENCES resumes(id) ON DELETE SET NULL,
    focus_areas     TEXT,                         -- JSON 数组: ["JVM", "分布式锁"]
    format          TEXT DEFAULT 'markdown',
    status          TEXT DEFAULT 'pending' CHECK(status IN ('pending','processing','completed','failed')),
    result_content  TEXT,                         -- 生成的 Markdown 原文
    word_count      INTEGER,
    error_msg       TEXT,
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    completed_at    DATETIME
);

CREATE INDEX idx_cram_status ON cram_tasks(status);
```

## 3. 向量数据库设计（ChromaDB）

ChromaDB 负责存储代码/文档的 **BGE-M3 1024 维向量**，并执行语义检索。

### 3.1 集合（Collection）命名规范
```text
project_{project_id}   # 例如: project_proj_abc123
```
**原因**：按项目隔离，避免多项目向量互相干扰，也便于删除项目时一键 `delete_collection`。

### 3.2 存储的 Metadata 字段（关键）
每个 Chunk（文档块）存入时必须携带以下元数据，以便检索结果回溯：

| 元数据字段      | 类型   | 说明                       | 示例                         |
| :-------------- | :----- | :------------------------- | :--------------------------- |
| `file_path`     | string | 文件相对路径               | `src/main/java/Service.java` |
| `chunk_type`    | string | `code` / `comment` / `doc` | `code`                       |
| `function_name` | string | 若属于函数体则提取函数名   | `handlePayment`              |
| `class_name`    | string | 所属类名                   | `PaymentController`          |
| `start_line`    | int    | 在源文件中的起始行         | 45                           |
| `end_line`      | int    | 结束行                     | 68                           |
| `language`      | string | 编程语言                   | `java`                       |

### 3.3 索引参数配置（Python 实现片段）
```python
import chromadb
from chromadb.config import Settings

client = chromadb.PersistentClient(path="./chroma_data")

collection = client.get_or_create_collection(
    name=f"project_{project_id}",
    metadata={
        "hnsw:space": "cosine",  # BGE-M3 推荐余弦相似度
        "hnsw:construction_ef": 200,
        "hnsw:M": 32
    }
)

# 添加向量（示例）
collection.add(
    ids=[chunk_id],
    embeddings=[bge_m3_vector],  # 1024维 float list
    metadatas=[{"file_path": "...", "function_name": "..."}],
    documents=["原始代码文本"]
)
```

### 3.4 检索策略（配合 API 的 `interact` 接口）
- **检索数量**：`n_results = 5`
- **检索类型**：`search_type="mmr"`（最大边际相关性），避免返回的 5 个 Chunk 内容高度雷同（例如重复的配置文件）。
- **前置过滤**：根据当前问题涉及的技术栈（如 `Redis`），在元数据中增加 `where={"chunk_type": "code"}` 缩小范围。

## 4. 关系库与向量库的数据一致性保障

| 操作                  | 关系库 (SQLite)                               | 向量库 (ChromaDB)                            | 一致性策略                                                   |
| :-------------------- | :-------------------------------------------- | :------------------------------------------- | :----------------------------------------------------------- |
| **新建/更新项目索引** | 更新 `chunk_count`, `last_indexed_at`         | 先 `delete_collection`（若存在）再逐批 `add` | **事务性**：索引失败时，关系库状态回滚为 `failed`，ChromaDB 集合标记为 `pending_delete`。 |
| **删除项目**          | 级联删除关联的 `function_graph` 和 `sessions` | 调用 `client.delete_collection()`            | 先删向量库（快速），再删关系库（软删除/硬删除）。            |
| **查询面试问题**      | 读取 `sessions` 获取当前技能指针              | 调用 `collection.query()` 检索代码片段       | 异步并行，但必须确保向量库检索成功后再调用 LLM，否则返回降级提示。 |

## 5. 关键查询性能优化（索引建议）

| 高频查询场景                                                 | 优化方案                                                     |
| :----------------------------------------------------------- | :----------------------------------------------------------- |
| **启动面试**：根据 `resume_id` 查 `skills`                   | 关系库建立 `idx_resumes_skills`（虚拟列索引）                |
| **检索上下文**：查最近 3 轮 `messages`                       | `CREATE INDEX idx_messages_recent ON messages(session_id, round_num DESC)` |
| **代码谱系追问**：查 `function_graph` 被调用关系             | `CREATE INDEX idx_graph_callee_lookup ON function_graph(callee_func)` |
| **检查项目状态**：`SELECT * FROM projects WHERE index_status='completed'` | 标准 B-Tree 索引 `idx_projects_status`                       |

## 7. 数据文件目录结构（本地部署建议）

```text
/data/
├── db/
│   └── interview.db          # SQLite 主库（含 WAL 日志）
├── chroma_data/              # ChromaDB 持久化目录（由 client 自动管理）
│   └── project_proj_abc123/
```

**安全建议**：`interview.db` 和 `chroma_data` 中存储了代码片段和简历，**禁止**将其提交至 Git 仓库，应在 `.gitignore` 中排除。
